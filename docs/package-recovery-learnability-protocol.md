# Locked synthetic package-recovery learnability diagnostic

Locked before any new neural probes or controller training. This is a separate diagnostic of the unchanged synthetic recovery task. The original reward-trained controller and the later LinUCB comparison remain valid failed teacher-gate experiments. No teacher–student communication or demo change is part of this study.

## Existing information benchmark

The synthetic sensor output is only one categorical signature (C0 alignment offset, C1 slip/rotation, C2 high resistance); no raw force or vibration trace exists. Four equiprobable hidden causes generate the signature using the fixed `cueProb` matrix in `tools/check_package_recovery.mjs`. The fixed success probabilities, delays, and escalation cost define expected net reward `1.4 P(success | cause, action) - 0.4 - 0.03 delay(action) - 0.20 1[action=2]`. The raw-signature Bayes policy maximizes its cause-posterior expected reward for each signature. The hidden-cause oracle maximizes cause-conditioned expected reward and is analysis-only. Neither reference supplies an action to a trained controller.

For a conservative, attainable neural reference, fit one Euclidean nearest-centroid cue classifier on each archived seed's 144 *training* three-MBON feature vectors with their observed sensor signatures, then apply it without refitting to that seed's 36 frozen held-out vectors. Choose the fixed raw-signature Bayes action for the decoded signature. This analytical classifier is not installed in a fly and uses no outcome or reward labels. It is a finite-sample reference, not the exact information-theoretic MBON optimum. The raw-signature optimum is an upper bound for MBON-only observations under the simulator's `cause → signature → neural activity` pathway; the hidden-cause oracle is a still higher, unavailable reference. Report population expectations and both archived held-out tapes separately.

## One prospective learning-feasibility test

Run only if the archived benchmark shows a useful neural policy above the untrained reference. Predetermined fresh neural identities: **16001 and 16002**. Their respective training/evaluation case RNG seeds are **2026110901/2026110902** and **2026110903/2026110904**. No replacement. Each stage uses 144 shuffled training cases (36 per hidden cause) and 36 independent held-out cases (9 per cause), with the fixed categorical sensor, action success probabilities, potential-outcome sampling, and reward/cost formula. The controller sees its observation and only the chosen action's sampled net reward. Hidden cause, outcome probabilities, counterfactual outcomes, and optimal actions are analysis-only.

Use the existing `LinUcbCore` unchanged in two matched, independently initialized arms: **raw observable signature** as three one-hot inputs, and **simulated neural** as the existing three standardized pooled MBON rates. Both have the same intercept, ridge 1, confidence bonus 0.5, action-value update, zero initial state, case order, reward tape, and 144-update budget. The raw arm is a non-neural learnability control, not a proposed fly input. For the neural arm, simulate the existing real-wiring VPN cue at 150 Hz during 0–240 ms with ordinary count reset at 50 ms and trial-keyed random streams; KC→MBON multipliers remain fixed. The decision features are measured at 240 ms. Because neural state resets on every case and synaptic weights are frozen, feature vectors may be computed once per case and reused at all frozen checkpoints. No network or controller update occurs during feature extraction or evaluation.

Before any reward training, fit one nearest-centroid signature decoder on each new seed's 144 training neural vectors and score its 36 separate evaluation vectors. **Neural-information gate:** at least **30/36** signatures recognized and an analytical decoded-signature policy with held-out cause-conditioned expected net reward **≥0.16** for **each** predetermined seed. This is a deliberately modest useful-information floor above the zero-initialized policy's approximate +0.093 on earlier tapes; it does not imply reliable recovery learning. If either seed fails, save the diagnostic and stop before controller training. Do not refit on evaluation or select a different neural population.

If both pass, train both arms for exactly **144** cases. Frozen checkpoints are **0, 24, 48, 96, 144** completed updates, on the same 36 held-out cases. Use a copied controller at each checkpoint; turn off the confidence bonus and all updates. Record every training choice, chosen reward, realized success, expected reward for analysis, all frozen case rows, action counts, controller changes, and neural-weight integrity. No controller may read the evaluation tape during training.

**Learning validity:** case IDs, causal observations, potential outcomes, training budgets, and held-out cases are matched between arms; both begin with zero reward estimates; frozen evaluation changes no controller weights; neural multipliers stay one. Failure is invalid, with no rerun or replacement. **Raw learnability gate:** each raw arm must finish at expected net reward **≥0.20** and use each action at least four times on held-out cases. If raw learning fails, the short reward budget/controller is not a valid test of neural learnability. **Neural learnability gate:** each neural arm must finish at expected net reward **≥0.20**, achieve **≥22/36** realized recoveries, choose each action at least four times, choose A2 on at least **60%** of C2 cases, and finish within **0.05** expected-reward units of its matched raw arm. All requirements apply to both seeds. Report early checkpoints and variability even on failure. These are new feasibility gates; they do not alter either earlier teacher gate.

The new result is written once to `data/package_recovery_learnability.json`. Stop after this test, whether it passes or fails. A pass would establish bounded synthetic independent learning under this fixed controller and observation, not teacher benefit, real robot performance, or biological dopamine plasticity.
