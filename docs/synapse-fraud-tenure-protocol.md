# Merchant-tenure teacher study — fixed before new API calls

The previous 12-message Gemini result and its old held-out accounts (`mock-060`–`mock-071`) were inspected as development evidence. They are excluded from this study's evaluation. This one candidate is fixed before teacher calls or inspection of the new held-out accounts.

**Hypothesis.** The original six features collapse a newly used merchant burst and a familiar merchant burst. Add `merchant_older_count`: the number of prior purchases at the candidate merchant strictly more than 24 hours before the candidate. Provide the same seventh numeric feature to Gemini and both local students. This is derived from transaction history, not the synthetic scenario name or label.

**Teacher.** `gemini-3.5-flash-lite`, the existing validated LOW/REVIEW/HIGH JSON schema, and the exact `TENURE_PROMPT` constant in `fraud/tenure_experiment.py`. Send only the seven rounded numeric features. Select 12 *unlabeled* training cases by observable history: `recent_count >= 2` and `same_merchant_count >= 2`, first six by row index with `merchant_older_count == 0` and first six with `merchant_older_count > 0`. No scenario name, ground truth, account ID, merchant ID, or test feature enters the teacher request. Reuse only responses cached for this exact prompt, model, and seven-feature input. Stop on an invalid response; never replace it with fixture advice.

**Learner and control.** Training accounts `mock-000`–`mock-047`. Both arms receive the same 72 true labels selected by `default_rng(720260 + 99).permutation(480)[:72]` and the same train-only seven-feature scaler. The teacher arm additionally receives 12 soft targets LOW=.05, REVIEW=.5, HIGH=.95 at weight .4. The matched control receives no teacher targets. Both use zero-initialized seven-feature logistic regression, 400 full-batch steps, step size .12, L2=.01. No threshold or architecture variation. Teacher messages are absent during inference.

**Evaluation.** One development run on `mock-048`–`mock-059`, followed by one final run on previously uninspected `mock-072`–`mock-083`, generated by the same seeded account procedure. `mock-060`–`mock-071` are never evaluated as new held-out evidence. Fixed binary threshold .5. Report TP/FP/FN/TN, fraud recall, precision, F1, false-positive rate, and message count for both arms. A positive result requires teacher F1 strictly above the matched control, fraud recall no lower, and false-positive rate no more than control + .02 on the new held-out set. Run the fixed candidate once on new held-out regardless of the development result; no tuning afterward.

**Limits.** Account-disjointness does not remove synthetic template repetition: every account has the same seven scenario families and order. Merchant tenure may nearly identify one generated scenario, so even a positive result would support only this synthetic benchmark, not live fraud accuracy or a general Gemini teaching benefit.
