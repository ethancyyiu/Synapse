# Codebase cleanup audit

## Baseline, recorded before edits

The repository had **538 non-Git files**, **153,771,021 bytes** (146.65 MiB), **126 Python/JavaScript source files**, and approximately **22,773 source lines** in `flyhero/`, `js/`, and `tools/`. This includes 320 JSON files in `data/`, 16 generated `.pyc` files (139,833 bytes), historical research logs, and the original demo. The counts include local generated files; they are not a measure of deployed browser code. The main page, legacy RPS page, and rhythm page are `index.html`, `legacy.html`, and `rhythm.html`.

Supported entry points include `python tools/serve.py`; `node tools/check_rps_challenge_demo.mjs`; `node tools/check_rps_demo.mjs`; `python -m flyhero.test`; and `python -m unittest flyhero.test_rps -v`. The README and lab notebook document many directly executable `tools/*.mjs` and `tools/*.py` research reproductions. The current Challenge loads `js/rps_challenge.js`, `js/rps_challenge_students.js`, `js/rps_challenge_checkpoints.js`, `js/rps.js`, `js/sim.js`, and brain rendering. `legacy.html` and `rhythm.html` use their separate entry scripts. Historical action-preference Strategy A/B and ablation scripts are retained even though the web page reads only their saved artifacts.

Before cleanup, both RPS smoke checks and both Python regression commands passed. `python -m unittest flyhero.test_rps -v` ran six tests with no failures. All **320** `data/*.json` files parsed, and the SHA-256 hashes of the three Strategy A archives, two Strategy B archives, and connectome ablation archive matched their independent-audit values. No known baseline failure was found.

## Audit and risk decisions

Inspected the repository file inventory, Python imports, browser module imports/entry points, documentation references, root scripts, generated caches, and saved-result files. The live Challenge, replay, legacy RPS, rhythm demo, neural simulator, tests, and action-preference/ablation reproduction scripts remain supported. Most of the 93 `.mjs` tools are directly runnable historical experiments; lack of a browser import does not make them dead. The 320 data JSON files, raw logs, protocols, independent audits, and failed results are research records. Preserve them.

Three small candidates are supported by stronger evidence:

1. `flyhero/rps_learning.py` imports `numpy as np` but never references `np` in that module. Removing the import does not change the RPS learning code or evaluation order.
2. The 16 `__pycache__/*.pyc` files are generated bytecode; `.gitignore` already excludes these caches. Python regenerates them when needed.
3. `research-loop.ps1` is an unreferenced, incomplete fragment. PowerShell's parser reports `Unexpected token '}'`; it is not a working supported entry point. The distinct `8hours_loop.ps1` and `8hours_loopssssssss.ps1` parse, so they are preserved despite their uncertain current use.

No neural, controller, simulator, RNG, timing, decoder, readout, CSS, or browser flow was changed. Apparent duplication among historical runners and the two demo pages is retained because those files encode separate locked protocols or supported user flows. No safe shared-helper consolidation was established; reducing their line count would risk deterministic behavior or reproduction commands.

## Cleanup result

- Deleted the 16 generated `.pyc` files and their now-empty cache directories (139,833 bytes). The final Python checks ran with `PYTHONDONTWRITEBYTECODE=1`; no cache was recreated.
- Deleted `research-loop.ps1` (3,061 bytes), the unreferenced, syntactically invalid fragment. The other PowerShell scripts were left intact.
- Removed the unused `numpy as np` import from `flyhero/rps_learning.py`. No function, controller, simulation equation, or research runner was changed.
- **No duplicated implementation was consolidated.** Similar-looking research runners represent different fixed protocols, and the two RPS pages have different supported flows. There was no proven behavior-preserving consolidation worth the risk before HackPrinceton.

This removed one active Python import line, roughly 100 lines of an incomplete PowerShell fragment, and 16 generated bytecode files. Including this new report, the repository now has **522 non-Git files** and approximately **153.64 MB**, down **16 files** and roughly **135 KB** from baseline. The small size reduction is intentional: the connectome and archived research data dominate the repository and must remain.

## Preserved candidates and later work

Keep the old experiment controllers, 93 direct-run `.mjs` tools, Python research scripts, original rhythm code, `data/`, `.research-loop/` logs, and `notes/experiments.log`: they may be needed to reproduce successful or failed findings. Keep `.nojekyll` for possible static hosting and the parseable but unreferenced PowerShell loops until their ownership and historical use are established. Many experiment runners repeat simulator setup, but changing shared floating-point or random-stream code could alter archived results. Those are inappropriate cleanup targets before the presentation.

The one worthwhile separate repair is the legacy page's shared-script/DOM mismatch. It should have its own behavior and browser test; it was not bundled into this code cleanup. The supported main demonstration remains `python tools/serve.py` then `http://localhost:8766/`.
